“Mount point busy” on one worker: multipathd and Longhorn

Summary

Pods with Longhorn volumes failed to start on k3s-worker-02 with an already mounted or mount point busy error. The cause was multipathd, which Ubuntu runs by default, claiming the block devices that Longhorn attaches over iSCSI. Excluding them in /etc/multipath.conf fixed it.

Root cause

Longhorn exposes each volume to the node as an iSCSI block device (/dev/sdX). On Ubuntu, multipathd sees those devices, tries to manage them as multipath devices, and holds them, so the actual mount fails with mount point busy.

Fix

A blacklist for the sd* devices, then a restart of the service and a flush of the existing maps: 

printf 'blacklist {\n    devnode "^sd[a-z0-9]+"\n}\n' | sudo tee -a /etc/multipath.conf
sudo systemctl restart multipathd && sudo multipath -F

What I'd do differently

This is now a step in my runbook for adding a node, before any workload lands on it, instead of something to discover from a failing pod. It is also the first thing to check whenever a Longhorn volume will not mount on a node and the other nodes are fine.

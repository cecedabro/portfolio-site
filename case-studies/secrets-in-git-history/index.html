A password in git history is still a password

Summary

My public homelab repository contained a Nextcloud admin password in a Helm values file and the public IP address of the router at my mother’s house in the Minecraft relay documentation. I removed both from the files in August, but they stayed in the git history. In October I rotated the password, moved the cluster’s secrets into OpenBao, and rewrote the history to remove both from every commit.

Root cause

Secrets lived in plain YAML next to the manifests. The August commit that cleaned them up only changed the current version of the files, and git keeps every old version. Anyone who cloned or browsed the repository could still read them.

Fix

Three steps:

  • Rotated the Nextcloud admin password, so the leaked one is worthless whatever happens to the history.
  • Moved secrets into OpenBao with External Secrets Operator. The repository now only says where a value goes, never the value itself.
  • Rewrote the history to remove the old password and the IP address from all commits, and force-pushed it. Existing clones have to be cloned again. The backup mirror I made first only lived in a temporary folder and is gone, so there is no way back to the old history.

What I'd do differently

Never commit a secret to begin with, and if one does get committed, rotate it first. Rewriting history is only cleanup: copies of the old commits may exist elsewhere, so only rotation makes the secret actually safe again.

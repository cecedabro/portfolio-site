The NAS link that ran at 100 Mbit/s for months

Summary

The laptop that serves my NFS share (media, Longhorn backups and k3s datastore backups) was linked to the network at 100 Mbit/s instead of 1 Gbit/s. The cause was the cable between the laptop and the switch. It stayed that way for months, because everything still worked, only slowly. I swapped the cable and added an alert so a slow link can no longer go unnoticed.

Context

Everything bulky in the cluster goes through that one link: media streaming, downloads, and the nightly backups. A fast-ethernet link tops out at roughly a tenth of what a gigabit link can carry, so it is a bottleneck for all of it at once.

Symptoms

I noticed it because I couldn't download and stream at the same time. Nothing reported an error; the link was simply slow.

Root cause

The cable between the control-plane laptop and the switch only linked at 100 Mbit/s, and nothing in the cluster measured link speed. Nothing failed, so nothing alerted. A degraded but working link looks exactly like a healthy one from the application side.

Fix

I swapped the cable. To make it visible next time, Prometheus now has a NodeLinkNotGigabit alert that fires when an ethernet interface that is up reports less than 1 Gbit/s for ten minutes. Checking the link speed with ethtool is also a step in the runbook for adding a node.

What I'd do differently

Check the negotiated speed when a machine is first cabled, not only whether it has a connection. Anything that fails by getting slower instead of breaking needs a metric, because nobody will report it.

Hardware

  • Laptop, 8GB RAM. Control plane — runs the k3s server and the NFS export. Only node with a battery, so it can shut down cleanly on a power cut.
  • HP EliteDesk (small form factor). Worker node 1 — general application pods + minecraft bedrock server.
  • HP EliteDesk (small form factor). Worker node 2 — general application pods.
  • HP Z400 workstation, GTX 1070. Tainted GPU node — currently only Jellyfin is GPU only since transcoding runs on it.

Decisions

Why bare metal instead of cloud

Mainly control, learning process but also costs.

I wanted to build this cluster as a means of learning. I wanted to learn how to set up the servers, how to run actual services on it and actually use these services. It also just felt really cool to have an at home server which is physically sitting in my room running my pods.

A physical bare metal server also gives way more control compared to the cloud. I can upgrade, change or even add more nodes whenever I want without changing my subscription. There simply is no subscription. It are my machines, running services I put on there. Of course since I'm basically running On Premise instead of Cloud, that means that I need to fix things when they are failing or broken. But thats also the charm of it and makes it all the more rewarding when things do work.

About costs, only now since I'm working as Cloud Engineer at the HvA in a project did I realise how expensive cloud subscriptions are! Simply running two containers for a tiny flask website costs me 10 euros already. Which is insane honestly in my opinion. I believe my cluster could easily run hundreds if not thousands of those containers and only bill me maybe a few bucks a month in energy costs. Of course I'm lucky to have been able to assemble my cluster very cheaply by contacting companies in my network for old office computers. But I still believe that running bare metal is just way cheaper (especially important for me considering im a student) compared to cloud.

NFS for media, Longhorn for state

I only use the NFS for media as a bulk storage device. I guess you could compare it to Blob storage. The SSD's from the nodes have been bundled together on Longhorn. This is to provide running pods with secure config volumes and make the whole cluster more resillient. As to why Longhorn specifically: it's what I found online to be a good pick when building the cluster simply.

Why the GPU node is tainted

This is the only node with a real dedicated GPU. It needs to be tainted so it actually picks up pods which require GPU work. For now its only the Jellyfin pod, since that requires some transcoding work when streaming big movies (For example a massive 52GB The Matrix HDR 4k movie file). I also briefly fiddled around with a Moonshine pod for remote gaming, but the outdated Xeon chip on the Z400 showed its age. Even when running Gemcraft...

Why Cloudflare Tunnel instead of open ports

This was both for convienience and securty. Since I live in student housing, I can't simply open a port. The modem has been hidden away from me and apart from my appartments local network and router I can't really configurate much. I literally simply can't open a port. Thats why I use a pi2 at my mom's house as a relay node for my minecraft bedrock server.

Cloudflare Tunnel doesn't require an open port from my network, its a pod running on my cluster which reroutes the traffic from another pod on the clusters network onto the open web through CloudFlare servers. This is both way more secure since my cluster isnt the first point of attack and because that way my ip isnt exposed.

Why NFS sits on the control plane

The control plane is the only node which has a battery. Its a laptop. That way, when for some reason my power would be cut or something happens to my house, at least the control plane has some ample time to manage the NFS and close its connection gracefully instead of abruptly.

I also thought it to be more sensible. I only have one control panel, but multiple worker nodes. The worker nodes should kind of randomly have pods running on them and distribute the work across each other, the control panel is my brain of the cluster so it made sense to me to have that be the point of connection to the NFS (which is basically an old second hand drive caddy where the drive configuration is JBOD).

Known gaps

  • There is no real Gitops yet. I do have some half assed jobs which run when pushed both this portfolio and the homelab repo, but no real deployment CI/CD stands as of now. This is one of the next natural steps to implement.
  • As of the backups, I do have Longhorn, but I haven't really set-up a real recovery plan nor backup routine. This is surely something I should add before I discover exactly why I had to set this up in the first place...
  • Although everything in the homelab YAML works with secrets where there is sensitive information, I know for sure that a few commits ago there were still passwords in the YAML. Even though these weren't dangerously important passwords, its still something I should fix one day by manually editing the Git history. As of now though, I can only ssh into the cluster with a Bitwarden ssh token and all passwords are securely locked behind the Bitwarden vault.
